# Архитектура

```text
index → bootstrap → cli
                   ├── auth → pat-store → окружение / хранилище ОС
                   ├── Asana-команды → sdk → Asana API
                   ├── api list/docs/call → sdk → официальный пакет asana
                   ├── request → raw-request → фиксированный Asana origin
                   ├── doctor → платформа / PATH / проверка PAT через Asana
                   └── help / man → встроенная справка
index → security → JSON stdout / ошибки stderr
```

`schemas` проверяет входные данные и ответы Asana. `sdk` нормализует коллекции и
ограничивает пагинацию. `security` удаляет известные процессу секреты из вывода;
`errors` переводит ошибки SDK и транспорта в стабильные коды.

`cli` проверяет команды и допустимые флаги до чтения авторизации.
Неизвестные и удалённые интерфейсы завершаются с `usage` (exit code 2).
Обычные команды чтения и записи, SDK и REST используют одну модель авторизации.
JSON-вывод одинаков для людей, скриптов и любых внешних клиентов.

Runtime не читает Git, конфигурацию репозитория или локальные привязки задач.
Запись выполняется непосредственно в Asana; локального журнала операций и механизма
повторного исполнения нет. `--dry-run` поддерживается только для task update/comment.
